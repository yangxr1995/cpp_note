## 设计模式概述
### 设计模式是什么
解决特定的问题的固定套路

### 设计模式是怎么发明的
前人在满足设计原则的基础上，实践总结，迭代出来的。

### 设计模式能解决的问题的特点
既有变化点，又有稳定点 的问题

如果问题只有稳定点或全是变化点则无法使用设计模式

### 使用设计模式的目的
修改少量代码，就能适应需求的变化

### 设计模式的基础
#### 面向对象的思想
- 封装
  - 隐藏实现，实现模块化
- 继承
  - 无需修改已有代码的基础上进行功能扩展
- 多态
  - 静态多态，函数重载
  - 动态多态，虚函数重写

#### 设计原则
- 依赖倒置
  - 高层模块不应该依赖底层模块，高层和底层模块都依赖抽象层。
```
                 ┌────────────┐                                         ┌────────┐

                 └───┬──┬──┬──┘                                         └────┬───┘                           
                     │  │  │                                                 ▼
               ┌─────┘  │  └────┐                        抽象层     ┌──────────────────┐                           
               │        │       │                                   └──────────────────┘
               ▼        ▼       ▼                                    ▲       ▲      ▲                        
           ┌─────┐  ┌─────┐  ┌─────┐                            ┌────┴┐  ┌───┴─┐  ┌─┴───┐                    
    底层   │车企1│  │车企2│  │车企3│                     底层   │车企1│  │车企2│  │车企3│                    
           └─────┘  └─────┘  └─────┘                            └─────┘  └─────┘  └─────┘
```

- 开闭
  - 对扩展开放，对修改关闭。
  - 封装，多态

- 面向接口
  - 封装

- 封装变化点
  - 封装，多态

- 单一职责
  - 封装

- 里氏继承
  - 多态

- 接口隔离
  - C++中使用类的权限限定词限定接口和用户隔离

- 组合由于继承

- 最小知道原则
  - 用户只需要看到他需要使用的接口
  - 封装


> [!NOTE]
> 设计原则是多个总结的，所以设计原则有重叠部分。

# 创建型
## 模板方法
- 定义
  - 定义一个算法骨架，将一些具体的操作延迟到子类，子类可以不改变算法结构，重新定义该算法的特定实现
- 稳定点
  - 算法骨架
- 变化点
  - 算法的某个具体操作

### 示例
- 背景
  - 某个品牌动物园,有一套固定的表演流程,但是其中有若干个表演子流程可创新替换,以尝试迭代更新表演流程;

```cc
#include <iostream>
using namespace std;

class ZooShow {
public:
    // 提供骨架流程，骨架流程中调用虚函数
    void Show() {
        // 如果子表演流程没有超时的话，进行一个中场游戏环节；
        if (Show0())
            PlayGame();
        Show1();
        Show2();
        Show3();
    }

private:
    void PlayGame() {
        cout << "after Show0, then play game" << endl;
    }

protected:
    // 封装变化点
    // 对其他用户关闭，但是子类开放的

    bool expired;
    virtual bool Show0() {
        cout << "show0" << endl;
        if (!expired) {
            return true;
        }
        return false;
    }
    virtual void Show2() {
        cout << "show2" << endl;
    }
    virtual void Show1() {
    }
    virtual void Show3() {
    }
};

// ZooShowEx10 类
class ZooShowEx10 : public ZooShow {
protected:
    virtual bool Show0() {  // 修正返回值以匹配基类的 virtual bool Show0()
        if (!expired) {
            return true;
        }
        return false;
    }
};

// ZooShowEx1 类
class ZooShowEx1 : public ZooShow {
protected:
    virtual bool Show0() {
        cout << "ZooShowEx1 show0" << endl;
        if (!expired) { // 里氏替换注释
            return true;
        }
        return false;
    }
    virtual void Show2() {
        cout << "show3" << endl;
    }
};

// ZooShowEx2 类
class ZooShowEx2 : public ZooShow {
protected:
    virtual void Show1() {
        cout << "show1" << endl;
    }
    virtual void Show2() {
        cout << "show3" << endl;
    }
};

// ZooShowEx3 类
class ZooShowEx3 : public ZooShow {
protected:
    virtual void Show1() {
        cout << "show1" << endl;
    }
    virtual void Show3() {
        cout << "show3" << endl;
    }
    virtual void Show4() {
        // 空实现
    }
};

int main (int argc, char *argv[]) {
    ZooShow *zs = new ZooShowEx2(); // 晚绑定
    zs->Show();
    zs = new ZooShowEx3();
    zs->Show();
    return 0;
}
```

- 代码结构
  - 基类中有骨架流程接口
  - 所有子流程对子类开放并且是虚函数
  - 通过多态实现扩展

- 符合哪些设计原则
  - 单一职责
  - 开闭
  - 依赖导致, 子类扩展依赖基类虚函数接口，使用者依赖骨架算法
  - 封装变化点， protected
  - 接口隔离
  - 最小知道原则, 用户只需要知道骨架算法的接口, 无需知道细节

- 如何扩展
  - 实现子类，复写子流程
  - 通过多态调用

## 观察者模式
### 定义
对象间一对多依赖关系，当被依赖对象状态变化时，所有依赖于他的对象都得到通知并更新

稳定点
一对多的依赖关系, 一变化时，多跟着变化
变化点
多增加，多减少.

背景

## 策略模式
定义一系列算法，把他们一个个封装起来，并且使他们可互相替换，该模式使算法可独立于使用它的客户程序而变化

解决问题
稳定点
客户程序于算法调用关系
变化点
算法变化

背景
商场有固定的促销活动，现在要提升促销活动的规格

```cc

class Context {

};

// 节日的具体算法是变化的，所以使用接口抽象他，实现客户程序调用节日算法稳定
class ProStrategy {
public:
    virtual double CalcPro(const Context &ctx) = 0;
    virtual ~ProStrategy();
};

// cpp
class VAC_Spring : public ProStrategy {
public:
    virtual double CalcPro(const Context &ctx){}
};
class VAC_Qixi : public ProStrategy {
public:
    virtual double CalcPro(const Context &ctx){}
};
class VAC_Qixi1 : public VAC_Qixi {
public:
    virtual double CalcPro(const Context &ctx){}
};

// 1. 接口隔离
//     通过依赖注入实现接口隔离
// 3. 开闭原则, 对修改关闭，对扩展开放
class Promotion { // 客户程序
public:
    Promotion(ProStrategy *sss) : s(sss) {}
    ~Promotion() {}
    double CalcPromotion(const Context &ctx) {
        // 客户程序调用节日算法是稳定的
        return s->CalcPro(ctx); // 2. 面向接口编程, Promotion类不关心节日类, 只关心节日类提供CalcPro接口
    }
private:
    ProStrategy *s; // 依赖注入, 将 Promotion 和 VAC_XXX类通过接口类隔离,让 Promotion 闭合
};

int main() {
    Context ctx;
    ProStrategy *s = new VAC_Qixi1();
    Promotion *p = new Promotion(s);
    p->CalcPromotion(ctx);
    return 0;
}
```

#### 版本四
```cc
#include <mutex>
#include <atomic>
class singleton {
public:
    static singleton* GetInstance() {
        // 原子load确保获取最新的数据
        // 解决 原子执行问题， 可见性问题，
        // 使用 memory_order_relaxed 不解决执行顺序问题，确保最高效执行
        singleton* tmp = _instance.load(std::memory_order_relaxed);
        // 内存屏障解决 执行顺序的问题，
        std::atomic_thread_fence(std::memory_order_acquire);
        if (tmp == nullptr) {
            std::lock_guard<std::mutex> lock(_mutex);
            tmp = _instance.load(std::memory_order_relaxed);
            if (tmp == nullptr) {
                tmp = new singleton;
                // 内存屏障确保 new singleton的指令不会越出内存屏障外执行
                // 保证了出内存屏障后 tmp 设置分配的内存且执行了构造
        // 内存屏障解决 执行顺序的问题，
                std::atomic_thread_fence(std::memory_order_release);
                _instance.store(tmp, std::memory_order_relaxed);
                atexit(destructor);
            }
        }
        return tmp;
    }
private:
    static void destructor() {
        singleton* tmp = _instance.load(std::memory_order_relaxed);
        if (nullptr != tmp) {
            delete tmp;
        }
    }

    singleton(){}; // 构造
    ~singleton(){};
    singleton(const singleton &) = delete; // 拷贝构造
    singleton& operator=(const singleton&) = delete;//拷贝赋值构造
    singleton(singleton &&) = delete;//移动构造
    singleton& operator=(singleton &&) = delete;//移动拷贝构造
    static std::atomic<singleton*> _instance;
    static std::mutex _mutex;
};

std::atomic<singleton*> singleton::_instance;//静态成员需要初始化
std::mutex singleton::_mutex; //互斥锁初始化
// g++ singleton.cpp -o singleton -std=c++11
```


原子变量解决了三个问题:
- 原子执行的问题
  - 一个操作由一组cpu指令完成，原子执行确保这组cpu指令要么能全部执行完，要么一条都无法执行
- 可见性的问题
  - 某CPU修改了私有缓存的数据，其他CPU是否可见
    - load 可以看见其他线程最新更新的数据
    - store 修改数据让其他线程可见
- 执行顺序的问题
  - 可设置 memory_order_release/memory_order_acquire/memory_order_release

内存屏障解决两个问题
  - 可见性问题
  - 执行顺序的问题

    - memory_order_acquire
      - 之后的代码不能优化到 memory_order_acquire之前
    - memory_order_release
      - 之前的代码不能优化到 memory_order_release之后
    - memory_order_relaxed
      - 不限制执行顺序

### 工厂模式
#### 工厂方法模式
- 特点：定义一个抽象工厂接口，由子类（具体工厂）决定创建哪种产品。每个具体产品对应一个具体工厂。
- 结构：
  - 抽象工厂接口（IFactory）：声明创建产品的抽象方法。
  - 具体工厂类（FactoryA、FactoryB等）：实现抽象工厂接口，负责创建对应产品。
  - 抽象产品接口（IProduct）：声明产品的统一方法。
  - 具体产品类（ProductA、ProductB等）：实现抽象产品接口。
- 优缺点：
  - 优点是符合开闭原则（新增产品只需加新工厂）；缺点是类数量增多（每个产品对应一个工厂）。

定义
定义一个用于创建对象的接口，让子类决定实例化哪一个类，工厂方法使得一个类的实例化延迟到子类

稳定点
创建同类对象的接口
同类对象有一个相关的职责
变化点
创建对象的扩展

```cc
class IExportFactory {
public:
    IExportFactory() : _export(nullptr) {}
    virtual ~IExportFactory() {
        if (_export) {
            delete _export;
            _export = nullptr;
        }

    // 使用模板方法实现对象的迟构造和具体方法的调用
    bool Export(const std::string &data) {

            _export = NewExport();
        }
        return _export->Export(data);
    }

protected:
    virtual IExport *NewExport() = 0; // 对用户隐藏了复杂的构造流程

private:
    IExport* _export; // 通过组合基类实现扩展
};
```

- 说明
  - IExport：抽象产品接口，定义了Export()方法
  - ExportXml/ExportJson/ExportTxt/ExportCSV：具体产品类，实现Export()方法
  - IExportFactory：抽象工厂类，定义NewExport()工厂方法
  - ExportXmlFactory/ExportJsonFactory/ExportTxtFactory/ExportCSVFactory：具体工厂类，实现NewExport()创建具体产品
- 设计模式特点
  - 开闭原则：添加新导出格式（如PDF）只需新增ExportPdf类和ExportPdfFactory，无需修改现有代码
  - 解耦：客户端（如main函数）只依赖IExportFactory，不依赖具体产品
  - 工厂方法：每个具体产品对应一个具体工厂，通过NewExport()方法创建产品
