## 设计模式概述
### 设计模式是什么
解决特定的问题的固定套路

### 设计模式是怎么发明的
前人在满足设计原则的基础上，实践总结，迭代出来的。

### 设计模式能解决的问题的特点
既有变化点，又有稳定点 的问题

如果问题只有稳定点或全是变化点则无法使用设计模式

### 使用设计模式的目的
修改少量代码，就能适应需求的变化

### 设计模式的基础
#### 面向对象的思想
- 封装
  - 隐藏实现，实现模块化
- 继承
  - 无需修改已有代码的基础上进行功能扩展
- 多态
  - 静态多态，函数重载
  - 动态多态，虚函数重写

#### 设计原则
- 依赖倒置
  - 高层模块不应该依赖底层模块，高层和底层模块都依赖抽象层。
```
                 ┌────────────┐                                         ┌────────┐

                 └───┬──┬──┬──┘                                         └────┬───┘                           
                     │  │  │                                                 ▼
               ┌─────┘  │  └────┐                        抽象层     ┌──────────────────┐                           
               │        │       │                                   └──────────────────┘
               ▼        ▼       ▼                                    ▲       ▲      ▲                        
           ┌─────┐  ┌─────┐  ┌─────┐                            ┌────┴┐  ┌───┴─┐  ┌─┴───┐                    
    底层   │车企1│  │车企2│  │车企3│                     底层   │车企1│  │车企2│  │车企3│                    
           └─────┘  └─────┘  └─────┘                            └─────┘  └─────┘  └─────┘
```

- 开闭
  - 对扩展开放，对修改关闭。
  - 封装，多态

- 面向接口
  - 封装

- 封装变化点
  - 封装，多态

- 单一职责
  - 封装

- 里氏继承
  - 多态

- 接口隔离
  - C++中使用类的权限限定词限定接口和用户隔离

- 组合由于继承

- 最小知道原则
  - 用户只需要看到他需要使用的接口
  - 封装


> [!NOTE]
> 设计原则是多个总结的，所以设计原则有重叠部分。

# 创建型
## 模板方法
- 定义
  - 定义一个算法骨架，将一些具体的操作延迟到子类，子类可以不改变算法结构，重新定义该算法的特定实现
- 稳定点
  - 算法骨架
- 变化点
  - 算法的某个具体操作

### 示例
- 背景
  - 某个品牌动物园,有一套固定的表演流程,但是其中有若干个表演子流程可创新替换,以尝试迭代更新表演流程;

```cc
#include <iostream>
using namespace std;

class ZooShow {
public:
    // 提供骨架流程，骨架流程中调用虚函数
    void Show() {
        // 如果子表演流程没有超时的话，进行一个中场游戏环节；
        if (Show0())
            PlayGame();
        Show1();
        Show2();
        Show3();
    }

private:
    void PlayGame() {
        cout << "after Show0, then play game" << endl;
    }

protected:
    // 封装变化点
    // 对其他用户关闭，但是子类开放的

    bool expired;
    virtual bool Show0() {
        cout << "show0" << endl;
        if (!expired) {
            return true;
        }
        return false;
    }
    virtual void Show2() {
        cout << "show2" << endl;
    }
    virtual void Show1() {
    }
    virtual void Show3() {
    }
};

// ZooShowEx10 类
class ZooShowEx10 : public ZooShow {
protected:
    virtual bool Show0() {  // 修正返回值以匹配基类的 virtual bool Show0()
        if (!expired) {
            return true;
        }
        return false;
    }
};

// ZooShowEx1 类
class ZooShowEx1 : public ZooShow {
protected:
    virtual bool Show0() {
        cout << "ZooShowEx1 show0" << endl;
        if (!expired) { // 里氏替换注释
            return true;
        }
        return false;
    }
    virtual void Show2() {
        cout << "show3" << endl;
    }
};

// ZooShowEx2 类
class ZooShowEx2 : public ZooShow {
protected:
    virtual void Show1() {
        cout << "show1" << endl;
    }
    virtual void Show2() {
        cout << "show3" << endl;
    }
};

// ZooShowEx3 类
class ZooShowEx3 : public ZooShow {
protected:
    virtual void Show1() {
        cout << "show1" << endl;
    }
    virtual void Show3() {
        cout << "show3" << endl;
    }
    virtual void Show4() {
        // 空实现
    }
};

int main (int argc, char *argv[]) {
    ZooShow *zs = new ZooShowEx2(); // 晚绑定
    zs->Show();
    zs = new ZooShowEx3();
    zs->Show();
    return 0;
}
```

- 代码结构
  - 基类中有骨架流程接口
  - 所有子流程对子类开放并且是虚函数
  - 通过多态实现扩展

- 符合哪些设计原则
  - 单一职责
  - 开闭
  - 依赖导致, 子类扩展依赖基类虚函数接口，使用者依赖骨架算法
  - 封装变化点， protected
  - 接口隔离
  - 最小知道原则, 用户只需要知道骨架算法的接口, 无需知道细节

- 如何扩展
  - 实现子类，复写子流程
  - 通过多态调用

## 观察者模式
### 定义
对象间一对多依赖关系，当被依赖对象状态变化时，所有依赖于他的对象都得到通知并更新

稳定点
一对多的依赖关系, 一变化时，多跟着变化
变化点
多增加，多减少.

背景
气象站更新数据中心的信息，数据中心处理数据，数据中心更新数据给两个不同的显示终端。

## 策略模式
定义一系列算法，把他们一个个封装起来，并且使他们可互相替换，该模式使算法可独立于使用它的客户程序而变化

解决问题
稳定点
客户程序于算法调用关系
变化点
算法变化

背景
商场有固定的促销活动，现在要提升促销活动的规格

```cc

class Context {

};

// 节日的具体算法是变化的，所以使用接口抽象他，实现客户程序调用节日算法稳定
class ProStrategy {
public:
    virtual double CalcPro(const Context &ctx) = 0;
    virtual ~ProStrategy();
};

// cpp
class VAC_Spring : public ProStrategy {
public:
    virtual double CalcPro(const Context &ctx){}
};
class VAC_Qixi : public ProStrategy {
public:
    virtual double CalcPro(const Context &ctx){}
};
class VAC_Qixi1 : public VAC_Qixi {
public:
    virtual double CalcPro(const Context &ctx){}
};

// 1. 接口隔离
//     通过依赖注入实现接口隔离
// 3. 开闭原则, 对修改关闭，对扩展开放
class Promotion { // 客户程序
public:
    Promotion(ProStrategy *sss) : s(sss) {}
    ~Promotion() {}
    double CalcPromotion(const Context &ctx) {
        // 客户程序调用节日算法是稳定的
        return s->CalcPro(ctx); // 2. 面向接口编程, Promotion类不关心节日类, 只关心节日类提供CalcPro接口
    }
private:
    ProStrategy *s; // 依赖注入, 将 Promotion 和 VAC_XXX类通过接口类隔离,让 Promotion 闭合
};

int main() {
    Context ctx;
    ProStrategy *s = new VAC_Qixi1();
    Promotion *p = new Promotion(s);
    p->CalcPromotion(ctx);
    return 0;
}
```

#### 版本四
```cc
#include <mutex>
#include <atomic>
class singleton {
public:
    static singleton* GetInstance() {
        // 原子load确保获取最新的数据
        // 解决 原子执行问题， 可见性问题，
        // 使用 memory_order_relaxed 不解决执行顺序问题，确保最高效执行
        singleton* tmp = _instance.load(std::memory_order_relaxed);
        // 内存屏障解决 执行顺序的问题，
        std::atomic_thread_fence(std::memory_order_acquire);
        if (tmp == nullptr) {
            std::lock_guard<std::mutex> lock(_mutex);
            tmp = _instance.load(std::memory_order_relaxed);
            if (tmp == nullptr) {
                tmp = new singleton;
                // 内存屏障确保 new singleton的指令不会越出内存屏障外执行
                // 保证了出内存屏障后 tmp 设置分配的内存且执行了构造
        // 内存屏障解决 执行顺序的问题，
                std::atomic_thread_fence(std::memory_order_release);
                _instance.store(tmp, std::memory_order_relaxed);
                atexit(destructor);
            }
        }
        return tmp;
    }
private:
    static void destructor() {
        singleton* tmp = _instance.load(std::memory_order_relaxed);
        if (nullptr != tmp) {
            delete tmp;
        }
    }

    singleton(){}; // 构造
    ~singleton(){};
    singleton(const singleton &) = delete; // 拷贝构造
    singleton& operator=(const singleton&) = delete;//拷贝赋值构造
    singleton(singleton &&) = delete;//移动构造
    singleton& operator=(singleton &&) = delete;//移动拷贝构造
    static std::atomic<singleton*> _instance;
    static std::mutex _mutex;
};

std::atomic<singleton*> singleton::_instance;//静态成员需要初始化
std::mutex singleton::_mutex; //互斥锁初始化
// g++ singleton.cpp -o singleton -std=c++11
```


原子变量解决了三个问题:
- 原子执行的问题
  - 一个操作由一组cpu指令完成，原子执行确保这组cpu指令要么能全部执行完，要么一条都无法执行
- 可见性的问题
  - 某CPU修改了私有缓存的数据，其他CPU是否可见
    - load 可以看见其他线程最新更新的数据
    - store 修改数据让其他线程可见
- 执行顺序的问题
  - 可设置 memory_order_release/memory_order_acquire/memory_order_relaxed

内存屏障解决两个问题
  - 可见性问题
  - 执行顺序的问题

    - memory_order_acquire
      - 之后的代码不能优化到 memory_order_acquire之前
    - memory_order_release
      - 之前的代码不能优化到 memory_order_release之后
    - memory_order_relaxed
      - 不限制执行顺序

### 工厂模式
#### 工厂方法模式
- 特点：定义一个抽象工厂接口，由子类（具体工厂）决定创建哪种产品。每个具体产品对应一个具体工厂。
- 结构：
  - 抽象工厂接口（IFactory）：声明创建产品的抽象方法。
  - 具体工厂类（FactoryA、FactoryB等）：实现抽象工厂接口，负责创建对应产品。
  - 抽象产品接口（IProduct）：声明产品的统一方法。
  - 具体产品类（ProductA、ProductB等）：实现抽象产品接口。
- 优缺点：
  - 优点是符合开闭原则（新增产品只需加新工厂）；缺点是类数量增多（每个产品对应一个工厂）。

定义
定义一个用于创建对象的接口，让子类决定实例化哪一个类，工厂方法使得一个类的实例化延迟到子类

稳定点
创建同类对象的接口
同类对象有一个相关的职责
变化点
创建对象的扩展

### 责任链模式
责任链模式是一种行为设计模式，允许你将请求沿着处理链传递，直到有一个处理者能够处理该请求为止。这种模式避免了请求发送者与接收者之间的耦合，让多个对象都有机会处理请求。

```cpp
#include <iostream>
#include <memory>
#include <string>

// 处理请求的抽象基类
class Handler {
protected:
    std::shared_ptr<Handler> nextHandler;

public:
    Handler() : nextHandler(nullptr) {}
    
    virtual ~Handler() = default;
    
    // 设置下一个处理者
    void setNext(std::shared_ptr<Handler> handler) {
        nextHandler = handler;
    }
    
    // 处理请求的接口
    virtual void handleRequest(const std::string& request) = 0;
};

// 具体处理者A
class ConcreteHandlerA : public Handler {
public:
    void handleRequest(const std::string& request) override {
        if (request == "A") {
            std::cout << "Handler A 处理了请求: " << request << std::endl;
        } else if (nextHandler != nullptr) {
            std::cout << "Handler A 无法处理，传递给下一个处理者" << std::endl;
            nextHandler->handleRequest(request);
        } else {
            std::cout << "没有处理者能处理请求: " << request << std::endl;
        }
    }
};

// 具体处理者B
class ConcreteHandlerB : public Handler {
public:
    void handleRequest(const std::string& request) override {
        if (request == "B") {
            std::cout << "Handler B 处理了请求: " << request << std::endl;
        } else if (nextHandler != nullptr) {
            std::cout << "Handler B 无法处理，传递给下一个处理者" << std::endl;
            nextHandler->handleRequest(request);
        } else {
            std::cout << "没有处理者能处理请求: " << request << std::endl;
        }
    }
};

// 具体处理者C
class ConcreteHandlerC : public Handler {
public:
    void handleRequest(const std::string& request) override {
        if (request == "C") {
            std::cout << "Handler C 处理了请求: " << request << std::endl;
        } else if (nextHandler != nullptr) {
            std::cout << "Handler C 无法处理，传递给下一个处理者" << std::endl;
            nextHandler->handleRequest(request);
        } else {
            std::cout << "没有处理者能处理请求: " << request << std::endl;
        }
    }
};

// 客户端代码
int main() {
    // 创建处理者
    auto handlerA = std::make_shared<ConcreteHandlerA>();
    auto handlerB = std::make_shared<ConcreteHandlerB>();
    auto handlerC = std::make_shared<ConcreteHandlerC>();
    
    // 构建责任链：A -> B -> C
    handlerA->setNext(handlerB);
    handlerB->setNext(handlerC);
    
    // 测试不同的请求
    std::cout << "测试请求 'A':" << std::endl;
    handlerA->handleRequest("A");
    
    std::cout << "\n测试请求 'B':" << std::endl;
    handlerA->handleRequest("B");
    
    std::cout << "\n测试请求 'C':" << std::endl;
    handlerA->handleRequest("C");
    
    std::cout << "\n测试请求 'D':" << std::endl;
    handlerA->handleRequest("D");
    
    return 0;
}
```

运行结果
```

Handler A 处理了请求: A

测试请求 'B':
Handler A 无法处理，传递给下一个处理者
Handler B 处理了请求: B

测试请求 'C':
Handler A 无法处理，传递给下一个处理者
Handler B 无法处理，传递给下一个处理者
Handler C 处理了请求: C

测试请求 'D':
Handler A 无法处理，传递给下一个处理者
Handler B 无法处理，传递给下一个处理者
Handler C 无法处理，传递给下一个处理者
没有处理者能处理请求: D
```


## 装饰器模式
装饰器模式是一种结构型设计模式，允许你通过将对象放入包含行为的特殊封装对象中来为原对象添加新的行为。

## 装饰器模式的核心思想

- **动态扩展功能**：在不修改原有类的基础上，动态地添加功能
- **组合优于继承**：通过组合的方式实现功能的扩展，避免继承带来的类爆炸问题
- **保持接口一致性**：装饰器和被装饰对象实现相同的接口


## C++ 实现示例
```cpp
#include <iostream>
#include <memory>
#include <string>

// 组件接口 - 定义可以被装饰的操作
class Beverage {
public:
    virtual ~Beverage() = default;
    virtual std::string getDescription() const = 0;
    virtual double cost() const = 0;
};

// 具体组件 - 基础饮料
class Coffee : public Beverage {
public:
    std::string getDescription() const override {
        return "咖啡";
    }
    
    double cost() const override {
        return 20.0;
    }
};

class Tea : public Beverage {
public:
    std::string getDescription() const override {
        return "茶";
    }
    
    double cost() const override {
        return 15.0;
    }
};

// 装饰器基类
class CondimentDecorator : public Beverage {
protected:
    std::shared_ptr<Beverage> beverage;

public:
    CondimentDecorator(std::shared_ptr<Beverage> bev) : beverage(bev) {}
    
    std::string getDescription() const override {
        return beverage->getDescription();
    }
    
    double cost() const override {
        return beverage->cost();
    }
};

// 具体装饰器 - 牛奶
class Milk : public CondimentDecorator {
public:
    Milk(std::shared_ptr<Beverage> bev) : CondimentDecorator(bev) {}
    
    std::string getDescription() const override {
        return beverage->getDescription() + " + 牛奶";
    }
    
    double cost() const override {
        return beverage->cost() + 5.0;
    }
};

// 具体装饰器 - 糖
class Sugar : public CondimentDecorator {
public:
    Sugar(std::shared_ptr<Beverage> bev) : CondimentDecorator(bev) {}
    
    std::string getDescription() const override {
        return beverage->getDescription() + " + 糖";
    }
    
    double cost() const override {
        return beverage->cost() + 2.0;
    }
};

// 具体装饰器 - 奶油
class Cream : public CondimentDecorator {
public:
    Cream(std::shared_ptr<Beverage> bev) : CondimentDecorator(bev) {}
    
    std::string getDescription() const override {
        return beverage->getDescription() + " + 奶油";
    }
    
    double cost() const override {
        return beverage->cost() + 8.0;
    }
};

// 客户端代码
int main() {
    // 基础咖啡
    auto coffee = std::make_shared<Coffee>();
    std::cout << coffee->getDescription() << " 价格: " << coffee->cost() << "元" << std::endl;
    
    // 咖啡 + 牛奶
    auto coffeeWithMilk = std::make_shared<Milk>(coffee);
    std::cout << coffeeWithMilk->getDescription() << " 价格: " << coffeeWithMilk->cost() << "元" << std::endl;
    
    // 咖啡 + 牛奶 + 糖
    auto coffeeWithMilkAndSugar = std::make_shared<Sugar>(coffeeWithMilk);
    std::cout << coffeeWithMilkAndSugar->getDescription() << " 价格: " << coffeeWithMilkAndSugar->cost() << "元" << std::endl;
    
    // 咖啡 + 牛奶 + 糖 + 奶油
    auto deluxeCoffee = std::make_shared<Cream>(coffeeWithMilkAndSugar);
    std::cout << deluxeCoffee->getDescription() << " 价格: " << deluxeCoffee->cost() << "元" << std::endl;
    
    std::cout << "\n--- 另一种组合 ---" << std::endl;
    
    // 茶 + 糖
    auto tea = std::make_shared<Tea>();
    auto teaWithSugar = std::make_shared<Sugar>(tea);
    std::cout << teaWithSugar->getDescription() << " 价格: " << teaWithSugar->cost() << "元" << std::endl;
    
    return 0;
}
```

## 组合模式

组合模式是一种结构型设计模式，允许你将对象组合成树形结构来表示"部分-整体"的层次结构，使得客户端可以统一对待单个对象和组合对象。

## 组合模式的核心思想

- **统一处理**：叶子节点和组合节点具有一致的接口
- **递归组合**：组合对象可以包含其他组合对象或叶子对象
- **树形结构**：天然适合表示层次结构数据

## C++ 实现示例

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <string>
#include <algorithm>

// 组件接口
class FileSystemComponent {
public:
    virtual ~FileSystemComponent() = default;
    virtual void display(int depth = 0) const = 0;
    virtual void add(std::shared_ptr<FileSystemComponent> component) {
        throw std::runtime_error("不支持添加操作");
    }
    virtual void remove(std::shared_ptr<FileSystemComponent> component) {
        throw std::runtime_error("不支持删除操作");
    }
    virtual std::vector<std::shared_ptr<FileSystemComponent>> getChildren() const {
        return {};
    }
};

// 叶子节点 - 文件
class File : public FileSystemComponent {
private:
    std::string name;
    int size;

public:
    File(const std::string& name, int size) : name(name), size(size) {}
    
    void display(int depth = 0) const override {
        std::string indent(depth * 2, ' ');
        std::cout << indent << "📄 " << name << " (" << size << " KB)" << std::endl;
    }
};

// 组合节点 - 文件夹
class Directory : public FileSystemComponent {
private:
    std::string name;
    std::vector<std::shared_ptr<FileSystemComponent>> children;

public:
    Directory(const std::string& name) : name(name) {}
    
    void display(int depth = 0) const override {
        std::string indent(depth * 2, ' ');
        std::cout << indent << "📁 " << name << std::endl;
        
        for (const auto& child : children) {
            child->display(depth + 1);
        }
    }
    
    void add(std::shared_ptr<FileSystemComponent> component) override {
        children.push_back(component);
    }
    
    void remove(std::shared_ptr<FileSystemComponent> component) override {
        auto it = std::find(children.begin(), children.end(), component);
        if (it != children.end()) {
            children.erase(it);
        }
    }
    
    std::vector<std::shared_ptr<FileSystemComponent>> getChildren() const override {
        return children;
    }
};

// 更复杂的组合节点 - 可计算大小的文件夹
class SizedDirectory : public Directory {
public:
    SizedDirectory(const std::string& name) : Directory(name) {}
    
    void display(int depth = 0) const override {
        std::string indent(depth * 2, ' ');
        std::cout << indent << "📁 " << getName() << " [总大小: " << calculateTotalSize() << " KB]" << std::endl;
        
        for (const auto& child : getChildren()) {
            child->display(depth + 1);
        }
    }
    
private:
    // 递归计算文件夹总大小
    int calculateTotalSize() const {
        int totalSize = 0;
        for (const auto& child : getChildren()) {
            // 如果是文件，直接累加大小
            if (auto file = std::dynamic_pointer_cast<File>(child)) {
                // 这里需要访问File的size，实际中应该通过接口获取
                // 为了简化示例，我们假设File有一个getSize方法
                totalSize += 10; // 简化处理
            }
            // 如果是文件夹，递归计算
            else if (auto dir = std::dynamic_pointer_cast<SizedDirectory>(child)) {
                totalSize += dir->calculateTotalSize();
            }
        }
        return totalSize;
    }
    
    std::string getName() const {
        return "Sized" + std::to_string(reinterpret_cast<uintptr_t>(this) % 1000);
    }
};

// 客户端代码
int main() {
    // 创建文件系统结构
    auto root = std::make_shared<Directory>("根目录");
    
    // 创建子文件夹
    auto documents = std::make_shared<Directory>("文档");
    auto images = std::make_shared<Directory>("图片");
    auto music = std::make_shared<SizedDirectory>("音乐");
    
    // 创建文件
    auto resume = std::make_shared<File>("简历.pdf", 1024);
    auto report = std::make_shared<File>("报告.docx", 2048);
    auto photo1 = std::make_shared<File>("照片1.jpg", 5120);
    auto photo2 = std::make_shared<File>("照片2.png", 4096);
    auto song1 = std::make_shared<File>("歌曲1.mp3", 8192);
    auto song2 = std::make_shared<File>("歌曲2.flac", 16384);
    
    // 构建层次结构
    root->add(documents);
    root->add(images);
    root->add(music);
    
    documents->add(resume);
    documents->add(report);
    
    images->add(photo1);
    images->add(photo2);
    
    // 音乐文件夹内再创建子文件夹
    auto rock = std::make_shared<Directory>("摇滚");
    auto jazz = std::make_shared<Directory>("爵士");
    
    music->add(rock);
    music->add(jazz);
    music->add(song1);
    music->add(song2);
    
    rock->add(std::make_shared<File>("rock1.mp3", 5000));
    rock->add(std::make_shared<File>("rock2.mp3", 6000));
    jazz->add(std::make_shared<File>("jazz1.mp3", 4000));
    
    // 显示整个文件系统
    std::cout << "文件系统结构:" << std::endl;
    std::cout << "====================" << std::endl;
    root->display();
    
    std::cout << "\n单独显示音乐文件夹:" << std::endl;
    std::cout << "====================" << std::endl;
    music->display();
    
    return 0;
}
```
