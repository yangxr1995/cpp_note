# 类、继承与虚函数

## 1. this、const 成员和静态成员

~~~cpp
class User {
public:
    void rename(std::string name) { name_ = std::move(name); }
    std::string name() const { return name_; }

    static int live_count();

private:
    std::string name_;
};
~~~

const 成员函数通过只读对象视角访问成员，可以被 const User 调用，并能与非 const 成员函数构成重载。静态成员函数没有 this，只能直接访问静态成员。静态数据成员是类级别实体，C++17 可用 inline static 在类内定义。

## 2. 指向成员的指针

~~~cpp
struct Student {
    int age;
    void show() const;
    static int count;
};

int Student::* data_member = &Student::age;
void (Student::*function_member)() const = &Student::show;

Student s{18};
s.*data_member = 20;
(s.*function_member)();

Student* p = &s;
(p->*function_member)();
int* static_member = &Student::count;
~~~

数据成员指针和成员函数指针不是普通指针。简单单继承 ABI 中，数据成员指针常看起来像偏移量；多重继承和虚继承下可能需要更复杂编码，成员函数指针大小也可能大于普通指针。不要把它们统一解释成绝对地址或固定偏移。

## 3. 对象布局和对齐

~~~cpp
struct Record {
    char tag;
    int value;
    void* payload;
};
~~~

对象通常包含填充字节以满足对齐，sizeof(T) 可能大于成员大小之和。空类对象也必须有非零大小。基类子对象、虚函数元数据、空基类优化和 [[no_unique_address]] 都会影响布局。

标准只对特定条件下的 standard-layout 类型提供较强布局保证。offsetof 不应随意用于含虚函数、复杂继承或非 standard-layout 类型。

## 4. 继承、隐藏、覆盖和切片

~~~cpp
struct Base {
    virtual void draw() const;
    virtual ~Base() = default;
};

struct Derived : Base {
    void draw() const override;
};
~~~

- 重载：同一作用域、同名、不同参数列表；
- 隐藏：派生类声明同名函数后，可能隐藏基类所有同名重载；
- 覆盖：派生类重写基类虚函数，推荐使用 override；
- 切片：派生对象按值复制到基类对象，只保留基类子对象。

~~~cpp
Derived d;
Base& ref = d;
ref.draw();     // 虚调用，运行时选择 Derived::draw
Base copy = d;  // 切片
~~~

## 5. 虚函数和动态分派

常见 ABI 会在多态对象中放置指向虚表的隐藏指针：

~~~text
对象地址 → vptr → 虚表 → 虚函数槽位 → 间接调用
~~~

这是常见实现，不是标准规定的字段名称或布局。编译器知道动态类型时可能去虚化，将调用优化为直接调用。

构造和析构期间，当前基类子对象不会分派到尚未构造的更派生部分：

~~~cpp
struct Base {
    Base() { draw(); } // 调用 Base::draw，不是 Derived::draw
    virtual void draw();
    virtual ~Base() = default;
};
~~~

构造函数不能是虚函数，静态成员函数也不能是虚函数。通过基类指针删除派生对象时，基类析构函数必须为 virtual，否则行为未定义：

~~~cpp
Base* p = new Derived;
delete p;
~~~

访问控制在编译期按静态类型检查，虚函数体选择在运行时按动态类型进行；因此派生覆盖函数为 private，不一定阻止通过 public 的基类接口调用。

## 6. 多重继承和虚继承

多重继承可能使一个最派生对象包含多个基类子对象，基类指针转换可能需要调整地址。虚继承使共享虚基类只保留一份，但通常增加元数据和运行时偏移计算。

“有二义性就使用虚继承”不是完整设计原则。企业代码应先考虑组合、接口隔离和清晰的所有权，再决定是否使用继承。虚基类由最派生类负责初始化。

不要清零多态对象：

~~~cpp
std::memset(this, 0, sizeof(*this)); // 可能破坏 vptr、非平凡成员和对象不变量
~~~

应使用成员初始化和值初始化建立对象不变量。
