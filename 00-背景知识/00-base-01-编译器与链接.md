# 编译器与链接

> 本文解释从源代码到可执行文件的全过程，并区分 C++ 语言规则、ABI 和编译器实现。

## 1. 构建流水线

~~~text
源文件
  ↓ 预处理：宏、#include、条件编译
翻译单元
  ↓ 编译：语法、类型、重载、模板、常量表达式
汇编源
  ↓ 汇编：机器码、符号、重定位、调试信息
目标文件 .o/.obj
  ↓ 链接：解析符号、合并节、应用重定位
可执行文件/动态库
  ↓ 装载：映射内存、解析动态依赖
进程
~~~

预处理器主要做文本处理，不理解 C++ 类型。宏可能破坏作用域、求值次数和运算符优先级，业务代码优先使用 constexpr、模板、函数和类型别名。

编译器在一个翻译单元中完成名字查找、类型检查、隐式转换、重载决议、模板实例化、常量求值和代码生成。目标文件不是完整程序，它还可能包含 .text、.rodata、.data、.bss、符号表、重定位项和调试信息。

## 2. 语言、ABI 和优化

| 层次 | 例子 | 是否能跨平台照搬 |
|---|---|---|
| C++ 语言规则 | const T& 能否绑定临时对象？析构顺序是什么？ | 通常可以 |
| ABI | 参数使用哪些寄存器？对象返回如何传递？ | 不能 |
| 编译器优化 | 是否内联？是否省略帧指针？ | 不能 |

C++ 不保证一定有栈帧、帧指针、固定的压栈顺序、某个名为 vptr 的字段，或某个函数一定通过 call/bl 指令调用。分析汇编时必须注明编译器、版本、架构、标准库、语言标准和优化选项。

## 3. 声明、定义和符号

~~~cpp
// a.h
int add(int, int);       // 声明

// a.cpp
int add(int a, int b) {  // 定义
    return a + b;
}

// use.cpp
int main() {
    return add(1, 2);    // 当前目标文件产生未定义引用
}
~~~

编译 use.cpp 时，编译器知道 add 的类型，但通常不知道最终地址；链接器负责把引用绑定到定义。

~~~cpp
// counter.cpp
int g_counter = 0;       // 定义，分配存储

// use.cpp
extern int g_counter;    // 声明，不是新的定义
~~~

命名空间作用域的 static 对象/函数具有内部链接，只在当前翻译单元可见。static 在局部变量、类成员上的含义不同，必须结合上下文判断。

## 4. 名称修饰和符号表

~~~cpp
namespace math {
int add(int, int);
double add(double, double);
}
~~~

C++ 为支持重载、命名空间、成员函数和模板，会把类型信息编码到外部符号名中。具体格式由 ABI 决定，不存在所有平台通用的“作用域 + 模板参数 + 函数名 + 参数列表”公式。c++filt 只能按特定 ABI 反修饰，MSVC 使用另一套格式。

readelf -Ws 常见字段：

| 字段 | 含义 |
|---|---|
| Type | FUNC、OBJECT 等 |
| Bind | LOCAL、GLOBAL、WEAK 等 |
| Vis | DEFAULT、HIDDEN 等可见性 |
| Ndx | 所在节的索引；UND 表示当前目标文件未定义 |
| Value | 地址或节内偏移，依文件阶段而定 |
| Size | 符号实体大小，可能为 0 |

Ndx 不是字节索引。模板实例显示为 WEAK、COMDAT 等，是工具链实现策略，不是 C++ 语言属性。

## 5. ODR、头文件和 C 接口

inline 的关键语言作用是允许相同定义出现在多个翻译单元中，并让这些定义代表同一个实体；它不是强制机器码内联。

~~~cpp
// api.h
#pragma once

inline int clamp_to_zero(int x) {
    return x < 0 ? 0 : x;
}

template<class T>
T square(T x) {
    return x * x;
}
~~~

模板实现通常放头文件，因为使用方需要看到定义才能实例化。普通外部变量应使用 extern 声明 + 单独定义，或使用 C++17 inline 变量，避免重复定义。

C/C++ 互操作通常只在头文件声明处使用 extern "C"：

~~~cpp
#ifdef __cplusplus
extern "C" {
#endif

int image_open(const char* path);
void image_close(int handle);

#ifdef __cplusplus
}
#endif
~~~

extern "C" 不会把 C++ 源码变成 C，也不会自动解决异常、类、模板、引用和标准库对象的跨语言 ABI 问题。

## 6. 观察工具

~~~bash
g++ -std=c++20 -O0 -g -S demo.cpp -o demo.s
g++ -std=c++20 -O2 -c demo.cpp -o demo.o
nm -C demo.o
readelf -Ws demo.o
objdump -drC demo.o
~~~

Windows/MSVC 可使用 cl、dumpbin 和调试器反汇编。建议同时对比 -O0 和 -O2；目标是验证语言语义和 ABI 假设，而不是背某个栈偏移。
