# 函数、重载与内联

## 1. 函数重载

函数名相同、参数列表不同可以构成重载；只改变返回值不能构成重载：

~~~cpp
void log(int);
void log(double);
void log(const std::string&);
// int log(int); // 错误：不能只靠返回值区分
~~~

重载决议会比较精确匹配、类型提升、一般转换、引用绑定、模板和用户定义转换。二义性应通过显式转换、命名区分或约束模板解决。

派生类同名函数会隐藏基类同名重载：

~~~cpp
struct Base {
    void f(int);
    void f(double);
};

struct Derived : Base {
    using Base::f;
    void f(std::string);
};
~~~

## 2. 默认参数

默认参数在调用点补入：

~~~cpp
int read_timeout();
void connect(std::string host, int timeout = read_timeout());

connect("db.example"); // 调用点补入 read_timeout()
~~~

要点：

- 默认参数必须从最右侧连续提供；
- 默认表达式通常在调用时求值，不是定义时固定结果；
- 名字查找和绑定主要发生在声明处；
- 默认值通常写在头文件声明中，定义处不要重复写；
- 已编译客户端可能已经把旧默认值编译进目标文件。

虚函数的默认参数是静态绑定的：

~~~cpp
struct Base {
    virtual void show(int n = 1);
};

struct Derived : Base {
    void show(int n = 2) override;
};

Base* p = new Derived;
p->show(); // 调用 Derived::show，但 n 使用 Base 的 1
delete p;
~~~

## 3. inline

~~~cpp
inline int add(int a, int b) {
    return a + b;
}
~~~

inline 不是强制把函数体复制到调用点。编译器可以内联没有 inline 的函数，也可以拒绝内联有 inline 的函数。

inline 的重要语言作用是允许相同定义出现在多个翻译单元中，并让它们代表同一个实体。类内定义的成员函数、模板定义也有相应的隐式内联/实例化规则。

内联可能：

- 消除调用、参数传递和间接分派；
- 暴露常量传播和死代码消除机会；
- 引起代码膨胀，损害指令缓存；
- 受函数指针、虚调用、动态库边界、LTO 和优化级别影响。

性能判断应通过基准和反汇编验证，不要根据 inline 关键字猜测结果。

## 4. 成员函数的编译视角

~~~cpp
struct Counter {
    void add(int n) { value += n; }
    int value{};
};

Counter c;
c.add(3);
~~~

成员函数可以粗略看成多了一个隐式对象参数：

~~~cpp
void Counter_add(Counter* this_, int n); // 仅作概念模型
~~~

const 成员函数通过只读对象视角访问成员；静态成员函数没有 this。具体传参寄存器和返回值位置由目标 ABI 决定。
