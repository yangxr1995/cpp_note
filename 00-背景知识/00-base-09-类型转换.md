# 类型转换

## 1. const_cast

const_cast 只改变 const/volatile 视角，不改变对象真实类型：

~~~cpp
void update(int&);

int x = 1;
const int& view = x;
update(const_cast<int&>(view)); // 合法，因为原对象 x 并非 const
~~~

如果原对象确实是 const，通过结果修改它是未定义行为。const_cast 不能把 int* 变成 double*。

## 2. static_cast

static_cast 用于编译器能理解关系的转换：

~~~cpp
struct Base { virtual ~Base() = default; };
struct Derived : Base {};

Derived d;
Base* base = &d;       // 安全的向上转换
Derived* p = static_cast<Derived*>(base);
~~~

向下 static_cast 不做运行时类型检查；只有 base 真指向 Derived 对象时才可安全使用。动态类型不确定时，考虑 dynamic_cast 或重新设计接口。

## 3. reinterpret_cast

reinterpret_cast 表达低层地址或位模式转换，但不会创建目标类型对象，也不会自动解决对齐、生命周期或严格别名问题：

~~~cpp
std::uintptr_t bits = reinterpret_cast<std::uintptr_t>(base);
~~~

把任意对象指针转换成另一个类型后直接解引用通常不安全。序列化应按字节格式处理，设备寄存器应使用平台接口，不能把 reinterpret_cast 当作万能转换。

## 4. dynamic_cast

源类型必须是多态类型。指针转换失败返回 nullptr，引用转换失败抛出 std::bad_cast：

~~~cpp
Base* base = get_base();

if (auto* derived = dynamic_cast<Derived*>(base)) {
    derived->specific_operation();
}
~~~

dynamic_cast 依赖 RTTI 和运行时元数据。频繁向下转型通常提示接口抽象需要改进，但在插件、边界适配和少量类型分派中可以是合理工具。

## 5. 选择原则

- 能不转换就不转换；
- 只去掉访问视角时才考虑 const_cast；
- 数值或明确继承关系优先 static_cast；
- 需要运行时检查的多态转换使用 dynamic_cast；
- reinterpret_cast 只留给明确的底层 ABI、设备或地址场景，并同时验证对齐、生命周期和别名规则。
