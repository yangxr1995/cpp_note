# 对象生命周期与内存

## 1. 存储期和生命周期

C++ 关心对象的生命周期和存储期，而不是简单的“堆/栈”二分：

- 自动存储期：通常是块作用域局部对象；
- 静态存储期：全局、命名空间和静态局部对象；
- 线程存储期：thread_local 对象；
- 动态存储期：动态分配获得的存储。

局部变量可能被优化到寄存器，甚至被消除，所以“局部变量一定在栈上”不是语言保证。

## 2. 初始化顺序

成员初始化顺序由成员声明顺序决定，不由初始化列表书写顺序决定：

~~~cpp
class Session {
public:
    Session(std::string host)
        : socket_(host),
          host_(std::move(host)) {}

private:
    Socket socket_;
    std::string host_;
};
~~~

构造通常遵循：虚基类 → 直接基类 → 成员（按声明顺序）→ 构造函数体；析构顺序相反。

初始化列表不是“默认构造后再赋值”，而是直接调用对应构造函数。类类型成员、const 成员和引用成员必须在初始化阶段完成构造或绑定。

## 3. new、operator new 和 delete

~~~cpp
Widget* p = new Widget(42);
delete p;
~~~

new-expression 概念上包含：调用 operator new 获取原始存储，在存储上调用构造函数，再返回类型化指针。operator new 只负责分配原始存储，不负责构造对象。delete 通常先调用析构函数，再调用匹配的 operator delete。

~~~cpp
int* a = new int;       // 默认初始化，值不确定
int* b = new int();     // 值初始化为 0
int* c = new int(3);    // 初始化为 3

delete a;
delete b;
delete c;
~~~

数组必须用 delete[]，单对象使用 delete。现代 C++ 优先使用 std::make_unique、std::make_shared、容器和 RAII，减少裸 new。

## 4. placement new

placement new 在已有存储上构造对象，不分配内存：

~~~cpp
#include <cstddef>
#include <new>

struct Widget {
    explicit Widget(int);
    ~Widget();
};

alignas(Widget) std::byte storage[sizeof(Widget)];
Widget* p = ::new (static_cast<void*>(storage)) Widget(3);
p->~Widget();
~~~

生产代码必须处理对齐、对象生命周期、异常路径和重复构造。原始内存池通常应封装在 RAII 类型中。malloc 只取得原始字节，不调用构造函数；不能把 malloc 得到的内存直接当成任意 C++ 对象。

## 5. Rule of Zero / Five

优先把资源交给标准 RAII 类型：

~~~cpp
class Image {
public:
    explicit Image(std::size_t n) : pixels_(n) {}

private:
    std::vector<std::byte> pixels_;
};
~~~

这遵循 Rule of Zero。若必须管理文件描述符、锁或堆内存，则要明确拷贝和移动语义。手写析构、拷贝构造、拷贝赋值、移动构造、移动赋值时，应按 Rule of Five 成套设计，并考虑自赋值、异常安全和移动操作的 noexcept。

## 6. 编译器视角

对象的构造和析构是语言可观察行为；对象是否落在栈、堆、寄存器以及中间对象是否被消除，是实现和优化问题。返回对象的拷贝消除和 NRVO 见 07-匿名变量和函数返回.md。
