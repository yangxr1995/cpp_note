# 临时对象、函数返回与拷贝消除

> 旧笔记中的“匿名变量”更准确的术语是**临时对象（temporary object）**。本章重点回答：对象什么时候构造、返回值到底有没有中间对象、移动构造和移动赋值分别何时发生，以及如何把这些语言规则映射到编译器实现。

## 1. 先记住四条结论

1. **临时对象是语言语义，不等于一定有一块可观察的栈内存。** 优化器可以让它直接在最终位置构造，甚至让它完全没有独立存储。
2. **“初始化”和“赋值”是两件事。** `T x = make();` 是初始化；`T x; x = make();` 是先默认构造，再进行赋值。
3. **C++17 对某些 prvalue 返回场景保证拷贝消除。** `return T(args...);` 直接初始化同类型目标时，不需要拷贝或移动构造。
4. **NRVO 仍是有条件的优化。** `return local;` 可能直接在调用者目标中构造 `local`，但标准并不要求所有场景都发生；即使没有 NRVO，C++ 也会优先尝试移动返回的局部对象。

## 2. 临时对象、完整表达式和生命周期

### 2.1 什么是临时对象

```cpp
struct Token {
    explicit Token(int);
    ~Token();
    void use() const;
};

Token(1).use();
```

`Token(1)` 创建一个没有名字的临时对象。它通常在包含它的**完整表达式**结束时销毁；上例中，完整表达式通常是这一条表达式语句。这里的“通常”很重要，因为引用绑定、异常和某些语言规则会影响生命周期。

临时对象不一定位于栈上，也不一定产生可见的构造/析构函数调用指令。只要程序的可观察行为保持一致，编译器就可以消除中间对象。

### 2.2 引用绑定的生命周期延长

```cpp
const Token& r = Token(1); // 临时对象延长到 r 的作用域结束
auto&& r2 = Token(2);      // 同样延长到 r2 的作用域结束
```

注意以下情况不能想当然地延长：

```cpp
const Token& get_ref() {
    return Token(1);       // 错误：返回后临时对象已销毁，形成悬空引用
}

void consume(const Token&);
consume(Token(3));         // 临时对象只保证活到这次调用的完整表达式结束
```

函数参数中的引用绑定不会把临时对象延长到被调用函数返回之后。企业代码中不要返回指向局部对象或临时对象的引用。

## 3. 初始化与赋值：最容易混淆的对比

```cpp
String make_string();

String a = make_string(); // 初始化 a

String b;                 // 先默认构造 b
b = make_string();        // 再用返回对象给 b 做移动赋值或拷贝赋值
```

第二种写法无法因为“返回值优化”而消除对 `b` 的赋值：`b` 已经是一个存在的对象，返回值只能作为赋值运算符的右操作数参与操作。若接口允许，应优先写成直接初始化，或使用 `emplace` 在最终位置构造。

## 4. 函数按值返回的语义模型

### 4.1 直接返回一个临时 prvalue：C++17 的保证拷贝消除

```cpp
struct Buffer {
    Buffer(int size);
    Buffer(const Buffer&);
    Buffer(Buffer&&) noexcept;
};

Buffer make_buffer(int n) {
    return Buffer(n);
}

Buffer b = make_buffer(1024);
```

在 C++17 及以后，这种“返回一个同类型 prvalue，再用它初始化同类型对象”的场景是保证拷贝消除的：抽象机直接把 `Buffer(1024)` 构造在 `b` 的存储位置。这里不是“先构造返回临时，再移动到 `b`”，而是根本没有那两个独立对象之间的移动步骤。

可以把它理解成编译器把目标位置一路传递给构造过程，但这是实现视角；源代码语义仍然是按值返回。

### 4.2 返回命名局部对象：NRVO 是可选的

```cpp
Buffer make_buffer(int n) {
    Buffer result(n);
    return result; // 可能发生 NRVO，也可能不发生
}
```

如果编译器选择 NRVO，`result` 直接在调用者为结果准备的存储区中构造；如果没有 NRVO，返回语句会优先把这个即将离开作用域的局部对象当作可移动对象，调用 `Buffer(Buffer&&)`，再不行才拷贝。

不要为了“强制移动”写成：

```cpp
return std::move(result); // 往往阻碍 NRVO；通常不应这样写
```

`std::move` 本身不移动任何东西，只是把表达式转换成 xvalue，使移动构造/移动赋值有机会被选中。

### 4.3 不要用有副作用的拷贝构造函数判断优化

```cpp
struct Probe {
    Probe();
    Probe(const Probe&); // 打印日志并不能代表所有构建的真实成本
    Probe(Probe&&) noexcept;
    ~Probe();
};
```

构造/析构日志的次数取决于：语言标准版本、是否是保证消除、是否发生 NRVO、编译器、优化选项以及类型本身。应把日志当作实验工具，不要把某个构建下的次数当作语言规则。

## 5. `operator+` 例子：为什么“先声明再赋值”不同

```cpp
class String {
public:
    String();
    String(const char*);
    String(const String&);
    String(String&&) noexcept;
    String& operator=(const String&);
    String& operator=(String&&) noexcept;
};

String operator+(const String& lhs, const String& rhs);

void example() {
    String s1;
    s1 = String("aaa") + String("bbb");
}
```

从语言层面可以确认：

1. `s1` 先被默认构造；
2. 两个字符串实参被构造，作为 `operator+` 的参数；
3. `operator+` 生成一个 `String` 返回值；
4. 该返回值作为右值传给 `s1` 的移动赋值运算符（若可用）；
5. 相关临时对象在各自完整表达式结束时销毁。

是否真的有多个独立存储、返回对象是否使用隐藏返回指针、`operator+` 内部是否被内联，都要看编译器和 ABI。若改成：

```cpp
String s1 = String("aaa") + String("bbb");
```

`s1` 是直接初始化目标，编译器有更大的机会把最终结果直接构造到 `s1` 中；在满足保证拷贝消除的具体 prvalue 场景下，甚至没有一次额外的拷贝/移动构造。

## 6. 返回值的 ABI 实现：隐藏的结果地址

对于不能直接放入寄存器的对象，一种常见实现是调用者准备目标空间，并把目标地址作为隐藏参数传入：

```cpp
// 源代码
String make();
String s = make();

// 仅作概念示意，真实 ABI 可能不同
void make(String* hidden_result);
make(&s);
```

这解释了为什么反汇编里经常能看到“调用者先给出一块对象地址，被调用函数拿这个地址调用构造函数”。但以下结论不能写成语言保证：

- 目标一定在调用者栈上；它也可能在堆、全局区或寄存器中；
- 一定存在一个叫“匿名变量”的独立对象；
- 所有类对象都使用隐藏指针；小对象可能直接用寄存器返回；
- 一个具体编译器的 `-O0` 栈布局在另一版本仍然相同。

## 7. 移动语义：移动的是资源，不是对象地址

```cpp
std::string source = "large data";
std::string target = std::move(source);
```

`std::move(source)` 只改变值类别，使 `source` 可以绑定到 `std::string&&`。真正的资源转移发生在 `std::string` 的移动构造函数中。移动后对象仍然存在，必须满足类型的基本不变量，但其具体值通常是“有效但未指定”。不要继续依赖它原来的内容。

移动构造和移动赋值并不自动出现于所有类型：用户声明析构、拷贝操作或移动操作，可能影响隐式生成规则。资源拥有类应优先遵循 Rule of Zero；确实自己管理资源时，再系统实现拷贝/移动构造、拷贝/移动赋值和析构，并处理异常安全。

## 8. `const` 引用和右值引用的区别

```cpp
void read(const String&); // 可接收左值和右值，但只能读
void take(String&&);      // 主要接收右值，可转移资源

String s;
read(s);
read(String("tmp"));
take(String("tmp"));
// take(s);              // 错误：命名变量 s 是左值
take(std::move(s));      // 明确允许从 s 转移资源
```

命名的 `T&&` 变量本身是左值：

```cpp
void f(String&& x) {
    use(x);            // x 是左值表达式
    use(std::move(x)); // 需要显式转成 xvalue 才会触发移动重载
}
```

模板中的 `T&&` 在类型推导后可能是转发引用，需配合 `std::forward<T>(x)` 完美转发；不能把所有 `&&` 都叫“万能引用”。

## 9. 如何做可复现的返回值实验

建议使用一个只记录构造/析构的类型，并分别比较：

```cpp
Thing make_prvalue() {
    return Thing{};
}

Thing make_named() {
    Thing x;
    return x;
}

void test() {
    Thing a = make_prvalue();
    Thing b = make_named();
    Thing c;
    c = make_prvalue();
}
```

在 GCC/Clang 上可分别尝试：

```bash
g++ -std=c++17 -O0 -fno-elide-constructors return.cpp
g++ -std=c++17 -O2 return.cpp
```

`-fno-elide-constructors` 只能帮助观察仍然允许省略的路径；C++17 的保证拷贝消除不能被它变回一组普通拷贝。想研究机器级结果时还要对比 `-S`、反汇编和不同优化级别。

## 10. 本章结论

- “临时对象”是 C++ 的生命周期概念，“栈上匿名变量”只是某次实现可能采用的形式。
- `T x = make()` 与 `T x; x = make()` 的性能模型不同，前者是初始化，后者包含赋值。
- C++17 的 prvalue 返回有保证拷贝消除；命名局部对象的 NRVO 仍需视编译器选择。
- 不要用 `std::move` 代替理解；它只是值类别转换，可能阻碍 NRVO。
- 企业级代码更应关注接口是否清楚、所有权是否明确、移动操作是否 `noexcept`、异常安全是否成立，而不是迷信某一份反汇编。
