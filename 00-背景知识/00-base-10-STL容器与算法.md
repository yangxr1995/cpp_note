# STL 容器与算法

## 1. 容器选择

| 容器 | 主要特性 | 常见复杂度/代价 |
|---|---|---|
| vector | 连续存储，缓存友好 | 末尾插入摊销 O(1)，中间插入/删除 O(n) |
| deque | 分段连续，支持两端操作 | 两端插入通常摊销 O(1)，不保证整体连续 |
| list | 双向链表 | 已有迭代器位置插入/删除 O(1)，随机访问 O(n) |
| map/set | 有序、唯一键/元素 | 查找/插入/删除 O(log n) |
| unordered_map/unordered_set | 哈希表、无序 | 平均 O(1)，最坏 O(n) |

vector 的扩容倍数不是标准固定值。reserve 减少扩容，resize 改变元素数量，二者不能混淆。

map 的键等价关系由比较器决定：如果 !comp(a,b) && !comp(b,a)，两个键等价。unordered_map 的 operator[] 在键不存在时会插入默认值；只读查询可使用 find 或 at，避免意外插入。

## 2. 迭代器和失效

~~~cpp
std::vector<int> values{1, 2, 3};

for (auto& value : values) {
    value *= 2;
}

for (const auto& value : values) {
    std::cout << value << '\\n';
}
~~~

for (auto value : values) 会复制元素；大对象通常使用 const auto& 或 auto&。

插入、删除、扩容和 rehash 后，旧迭代器、指针、引用是否仍有效取决于容器和具体操作。工程代码应查对应容器的失效规则，不能笼统地说“迭代器总是安全”。

## 3. 算法和比较器

~~~cpp
std::sort(values.begin(), values.end(),
          [](int a, int b) { return a > b; });
~~~

泛型算法通过迭代器和操作对象工作。比较器必须满足算法要求的严格弱序等语义约束；算法复杂度、迭代器类别和元素移动/拷贝代价共同决定性能。

## 4. 编译器视角

vector 的连续内存让编译器和 CPU 更容易利用局部性，但扩容可能搬移元素。list 的节点插入可以稳定已有节点地址，却带来额外指针和缓存未命中。unordered 容器平均查找快，但 rehash、哈希质量和最坏复杂度必须纳入设计。

容器选择应先问：

1. 是否需要连续内存或稳定地址？
2. 是否主要在尾部、两端还是中间插入？
3. 是否需要排序遍历？
4. 是否允许键不存在时插入？
5. 哪些操作会使迭代器、指针和引用失效？
6. 元素的移动、拷贝和析构成本是多少？
